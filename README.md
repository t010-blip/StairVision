# 무한의 계단 Vision Analyzer · 프로토타입 v0.1

게임 화면을 기기 안에서 분석해 다음 행동(CLIMB / TURN_LEFT / TURN_RIGHT / UNKNOWN)을 오버레이에 표시하고,
사용자가 켰을 때만 오르기·방향 전환 버튼을 대신 누르는 Android 앱입니다.

## 빌드

1. Android Studio(Ladybug 이상)에서 이 폴더를 엽니다. Gradle 동기화가 자동으로 진행됩니다.
2. USB 디버깅을 켠 기기를 연결하고 ▶ Run을 누릅니다.
   - 명령줄: `./gradlew installDebug`
   - 분석 로직 단위 테스트: `./gradlew test`
3. 요구 사항: Android 8.0(API 26) 이상, JDK 17.

> Android 13 이상에서 APK 파일을 직접 설치했다면 접근성 스위치가 회색으로 잠길 수 있습니다.
> 설정 → 앱 → 계단 Vision → 오른쪽 위 ⋮ → "제한된 설정 허용" 후 다시 켜세요.

## 사용 순서

1. 앱에서 ① 다른 앱 위에 표시 권한을 켭니다. 자동 입력을 쓸 때만 ② 접근성도 켭니다.
2. ③ 분석 시작 → **전체 화면** 공유를 고릅니다.
3. 게임에서 캐릭터가 계단 위에 선 화면을 띄우고 오버레이의 **보정캡처**를 누릅니다.
4. 앱의 ④ 보정에서 네 곳을 차례로 누릅니다.
   1. 현재 발판: 캐릭터에 가려지지 않은 부분(발 바로 아래)
   2. 다음 발판: 바로 위 칸(왼쪽이든 오른쪽이든)
   3. 오르기 버튼
   4. 방향 전환 버튼
   
   아래 "검증" 줄이 다음 발판 방향을 맞게 보여주면 저장합니다.
5. 게임으로 돌아가 오버레이 판단이 화면과 맞는지 먼저 확인합니다.
6. 자동 입력: 게임 시작 직전 오버레이 방향이 실제 캐릭터 방향과 같은지 확인(다르면 **방향↔**) 후 **자동**을 켭니다.
   **■ 중지**는 분석과 입력을 즉시 모두 멈춥니다.

오버레이 패널은 글자 부분을 끌어 옮길 수 있습니다. 계단 주변과 게임 버튼을 가리지 않는 곳에 두세요.
(전체 화면 캡처에 패널도 찍히고, 자동 탭도 패널이 먼저 받습니다.)

## 동작 방식

| 단계 | 구현 | 파일 |
| --- | --- | --- |
| 캡처 | MediaProjection → ImageReader, 절반 해상도 | `CaptureService.kt` |
| 인식 | 현재 발판의 색 구성(최대 4색)을 매 프레임 학습해 위 줄·아래 줄 후보 4곳과 비교. 영역을 세 띠로 나눠 아이템 가림에 대응 | `analysis/StairAnalyzer.kt` |
| 판단 | 한쪽에만 발판이 확실할 때만 방향 결정, 아니면 UNKNOWN | `analysis/Model.kt` `decide()` |
| 안정화 | 연속 프레임 일치, 입력 후 옛 프레임 무시, 발판 소실 시 중단 | `analysis/DecisionGate.kt` |
| 표시 | 행동·방향·신뢰도·점수·처리 시간·자동 상태 | `OverlayController.kt` |
| 입력 | 접근성 `dispatchGesture` 30ms 탭 | `InputService.kt` |
| 보정 | 저장한 화면 한 장에서 네 곳 지정, 발판 색 자동 추출 | `CalibrationActivity.kt` |

방향 전환 버튼은 전환과 동시에 한 칸 오르므로, 회전도 입력 1회로 처리하고 내부 방향만 뒤집습니다.

### 안전 장치

- UNKNOWN, 낮은 신뢰도, 프레임 간 판단 불일치 → 입력 없음
- 입력 후 `settleMs`(기본 90ms) 이전에 찍힌 프레임은 무시 → 회전 직후 옛 화면을 보고 한 칸 더 오르는 사고 방지
- 확실한 판단이 1.2초 넘게 없으면(게임 오버·화면 전환·인식 실패) 자동 입력 OFF, 방향은 시작 방향으로 초기화
- 입력 전달 실패, 화면 잠금, 상태바의 공유 중지 → 자동 입력 OFF 또는 분석 종료
- 자동 입력은 앱을 켤 때마다 OFF로 시작

## 계획서와 다른 점 · 한계

- **OpenCV 미사용**: 무한의 계단은 카메라가 캐릭터를 따라가므로 다음 발판이 올 수 있는 자리가 두 곳뿐입니다.
  세 영역 색 비교로 충분하고 프레임당 수 ms 안에 끝납니다. 테마가 다양해지면 V0.2에서 `StairAnalyzer`만 OpenCV 구현으로 바꾸면 됩니다.
- **방향은 이전 발판으로 판단**: 캐릭터 아래 이전 발판의 반대쪽이 현재 방향입니다. 게임 시작 직후처럼 이전 발판이 없을 때만 입력 이력으로 추적한 값(오버레이에 '(추적)')을 씁니다.
- **계단 스킨·아이템**: 기준 색을 매 프레임 현재 발판에서 다시 읽고, 검사 영역의 세 띠 중 두 띠만 맞으면 발판으로 봅니다.
- **속도**: 기본값(연속 2프레임 + 90ms 대기)에서 초당 약 7~8칸이 상한입니다. 기기에서 측정 후 설정에서 조정하세요.
- 실제 게임 화면으로는 시험하지 못했습니다. 합성 화면 단위 테스트(19개)만 통과했습니다.

## 이용 범위

개인 기기에서의 비전 기술 시험용입니다. 게임 이용약관이 자동 입력을 금지할 수 있으므로
PvP·협동전·랭킹 기록에는 사용하지 말고, 오프라인 단독 플레이에서만 시험하세요.
Google Play는 다른 앱의 게임 플레이에 영향을 주는 앱을 금지하므로 스토어 배포 대상이 아닙니다.

## 좀비고 크리스마스 익스프레스 2 가이드 (v0.2 추가)

앱의 "크익2 가이드 열기"를 누르면 게임 위에 가이드 패널이 뜹니다.

- **+주문**: 화면 상단에 나온 주문을 고릅니다. 세트 주문은 "세트"를 누르고 피규어 두 개를 차례로 고릅니다.
- 패널에 주문마다 `꽃+꽃 → 화로 → 피규어`, 세트면 `포토부스 → 포장 → 보따리` 순서가 나옵니다.
- **꽃 합계**: 열린 주문 전체에 필요한 꽃 개수. 가장 먼저 필요한 꽃이 앞에 옵니다.
- 끝난 주문은 눌러서 지웁니다. **접기**는 첫 주문과 합계만 남깁니다. 패널 제목을 끌면 위치를 옮길 수 있습니다.

레시피 24종은 나무위키 "좀비고등학교/이벤트/크리스마스"의 크리스마스 익스프레스 2 표를 따릅니다(`zombie/Recipes.kt`).
주문 카드 자동 인식은 모드가 열려 실제 화면을 확인한 뒤 계단 분석과 같은 캡처 파이프라인으로 추가할 예정입니다.
